The architecture you've built
             EmployeeController
                    ↓
             EmployeeService
              (interface)
                    ↓
          EmployeeServiceImpl
            (actual logic)
                    ↓
           EmployeeRepository
                    ↓
                  MySQL

You've actually learned several important concepts while building this:

Interface → defines what the service can do
Implementation class → defines how it does it
@Service → tells Spring to manage the service
@Autowired → Spring provides the repository dependency
Getter/setter → access to private entity fields
List<Employee> → collection of Employee objects
Optional<Employee> → employee may or may not exist
Repository → handles database operations
Service → handles application/business logic

This is where your project starts becoming a real REST API.

#CONTROLLER: The Controller is the entry point for HTTP requests.

            For example, when Postman sends:

            GET /api/employees

            the Controller receives that request and says:

            "The user wants all employees. I'll ask the Service for them."

            The Controller shouldn't directly talk to MySQL.

Annotation: @RestController

    At the top of EmployeeController, we'll use:

    @RestController

    This tells Spring:

    "This class is a Controller that handles HTTP requests and returns data such as JSON."

    For example, an Employee object returned by the Controller can become:

    {
      "id": 1,
      "firstName": "John",
      "lastName": "Smith",
      "email": "john@example.com"
    }
